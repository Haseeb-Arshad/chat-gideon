Talk to GIDEON

GIDEON · the card system · planned 13 September 2026, being built in phases

Cards that know what they are showing

Today GIDEON draws one kind of card. This plan grows it into a system: four sizes, twenty blocks, tables, charts, timelines, Mapbox maps, video and broadsheet layouts, crafted from evidence that code captured rather than words a model typed, and gathered by narrow skills that are tested against each other so the wrong one does not fire.

“Like Minecraft” is read as crafting from blocks. A card is not a template with blanks; it is small typed blocks arranged by a named recipe, from materials a skill gathered. Cards already on screen are materials too, so two can be crafted into a third.

“Skills” is read as GIDEON’s own abilities at runtime: narrow tools with one job and a written boundary. A checklist for adding one closes the specification, and can become a repository skill file later.

2

What is kept, and what stops it growing

Kept, in every new card

  • The card never delays the voice. It is drawn beside the answer.
  • No number the brief did not state. grounded() removes it with whatever carried it.
  • “No card” is an answer. An empty pane says less than no pane.
  • Three layers per card, and only the card in front refracts.
  • The choreography: the face docks, a card peeks, the shelf holds, the judge brings a card back.
  • Facts brighten as they are said.
  • A guess’s cards wait with the guess.

What stops it growing

  1. One flat shape. A field and a branch per feature; no card could hold two.
  2. One size, 700 px, 960 at most.
  3. Only what the brief said aloud: five facts, never a table.
  4. The layout model writes the numbers, so grounding has to delete them.
  5. Whole or nothing: the fast parts wait for the slowest.
  6. Known by title only to the speaking model.
  7. Nothing changes: no sorting, zooming, playing.
  8. The shelf is lost on reload.

3

The rules every card obeys

R1
The voice never waits for the screen.A skill hands over its words first; the card follows beside them.
R2
Nothing on screen a source did not say.Copied from a response, taken from the brief, or computed in code and labelled so.
R3
Values are referenced, never retyped.The composer names where a value is; code copies it. A model cannot mistype a number it never writes.
R4
A card earns its size.Enough points for a chart, cells for a table, coordinates for a map, or it steps down.
R5
One material.The same liquid glass everywhere; dense content sits in calmer wells.
R6
Narrow skills with sharp edges.One job each, a stated boundary, and tests against the neighbours.
R7
Unobservable until real.Data skills are read-only; a guess may run them, and nothing shows until it is kept.
R8
Measured before it ships.Routing, grounding, time to card and frame size each have a gate.
R9
It degrades like the rest of GIDEON.No token, no WebGL, no key: a smaller card, a still, or no offer at all.

4

Materials, blocks, recipes, skills, crafting

Crafting is the model of the whole system. A skill gathers materials, evidence captured by code with where and when it came from. Blocks reference those materials. A recipe arranges blocks into a card. Cards on screen feed back in as materials, which is what lets two of them be crafted into a third.

Keeping the wrong skill from firing

Five layers, cheapest first, so most mistakes are stopped before they cost a round of silence.

  1. Narrow jobs, generated descriptions.Each skill’s manifest holds its one job, when to use it, what it is never for and which tool is, three examples and two counter-examples. The description is generated from it, so none can be vague, and no description example is reused in the test corpus.
  2. The boundary table.Written before a skill is built, for every pair that could be confused, and turned straight into test cases. Filter it below.
  3. Guards inside each skill.Arguments are checked before any request leaves; a call that does not fit is refused in one sentence the model can act on (“That is beyond the forecast; use research”).
  4. Recipes gated on materials, in code.The composer is only offered recipes its materials qualify for. It cannot choose a trend when no series has four points.
  5. A corpus that gates every change.About 240 utterances through the real speaking model with every tool stubbed, printed as a confusion matrix.

How a card is made

At the skill the turn splits in two. Its words go straight back to the speaking model, which starts talking. Its evidence goes down the card path, and the only way a value reaches the screen is through the resolver.

Richer than the brief, and still only what the brief relied on

The desk already sees every result and page. It now keeps them as materials, stamped with their URL and when they were fetched: eight results of up to 900 characters per search and pages of up to 10,000, not just the 180 words that were spoken. Results the brief did not cite are left out, so a card cannot bring back a stale page the desk decided against; materials from data tools are always kept, because the desk called those on purpose.

The composer writes pointers; the resolver writes values

What the composer writes

{ "slot": "lead", "type": "stat",
  "value":  { "from": "m2", "pick": "last" },
  "change": { "derive": "percent-change",
              "of": { "from": "m2", "pick": "first" },
              "to": { "from": "m2", "pick": "last" } },
  "label": "Passengers, latest year" }

What reaches the browser

{ "id": "b1", "slot": "lead", "type": "stat",
  "value": "4.9 M", "label": "Passengers, latest year",
  "change": { "value": "+58%", "direction": "up",
    "derived": { "formula": "(4.9 − 3.1) ÷ 3.1",
                 "inputs": ["m2@2014", "m2@2025"] } },
  "cite": [0] }  // sample series
PointerMeans
{ from }a whole material
{ from, field }one field of a record
{ from, row, column }one table cell by its labels, never by index, so a miscount cannot pick the wrong row
{ from, pick }first, last, max, min or at:2020 of a series
{ derive, … }change, percent change, CAGR, rank or distance, computed in code and shown with its formula

The validator keeps today’s number check and adds five more: quotes word for word, dates found in a material, one unit per row and axis, the recipe’s minimums after resolution, and the fold budget. A card that fails steps down its chain (trend, figure, answer, no card); a block that fails alone is dropped and the recipe closes over the gap.

The schema and the wire

The card

interface CardV2 {
  schema: 2
  recipe: RecipeId
  size: 'glance' | 'standard' | 'wide' | 'feature'
  query: string
  title: string          // shelf, director, speaking model
  blocks: Block[]        // resolved values only
  sources: CardSource[]
  asOf: string | null
  freshForMs: number | null
  origin: { tool, args } // so "refresh it" can run it again
  controls: CardControl[]
  mentions: Mention[]
  partial: boolean       // more blocks are coming
}

The materials behind it

type Material =
  | { kind: 'record', subject, fields }
  | { kind: 'table',  columns, rows }
  | { kind: 'series', name, unit, x, points }
  | { kind: 'geo',    features }
  | { kind: 'events', items }
  | { kind: 'stories', items }
  | { kind: 'text',   text }
// every one: { id, source: { url, title, fetchedAt } }
// built by code from responses; never by a model;
// kept on the server, keyed by card, for crafting

Protocol version 3

  • ready gains features and the public mapboxToken; /api/config carries the same for the HTTP fallback.
  • card carries a CardV2 or today’s card, drawn through an adapter, so a tab left open on an older build keeps working.
  • card_patch is new: blocks upserted by id; a patch for a card no longer on screen is ignored.
  • stage gains { op: 'control', card, control, value }; turn.screen gains the open card’s digest, 400 characters at most.
  • Bounds in code before sending: card 64 KB, patch 32 KB, 50 table rows, 400 points per series, 50 map features, 500 route coordinates. Cloudflare accepts 32 MiB WebSocket messages since October 2025, so these bounds are for the phone’s radio and the renderer, not the platform.

The room is a moving shader that changes colour with the mood, so the wells were computed rather than chosen. Data colours on those wells

  • All eight, in this fixed order, pass every check on all six wells at 72%: lightness, chroma, colour-blind and normal-vision separation, 3:1 contrast.
  • At 60%, green falls to 2.76:1 on the happy well.
  • Wells are tinted at 74%, just past the measured line.
  • Maps and charts where any two marks can touch use only the first three.

Text on those wells (4.5:1 needed)

  • Primary ink #f6f8ff: 14.84:1 at worst.
  • Today’s fact labels, ice at 55%: 4.69:1, a narrow pass; in wells they move to 70% (6.70:1).
  • A common muted grey, #898781: 4.39:1, fails on the curious and happy wells.
  • Proposed muted and axis ink #a9b1bd: 7.28:1.

A unit test recomputes both tables from PALETTES, so a change to the room that makes a well unreadable fails the build rather than a card.

Type, colour and motion

  • GT Alpina for headlines, mastheads and decks, and the number on a figure card, which is GIDEON’s voice. Frances for body text and every number inside a data block. Plex Mono for kickers, datelines, units and axes. (This page substitutes the project’s own fallbacks: Fraunces, Manrope, IBM Plex Mono.)
  • Tabular figures only where digits line up; a standalone number uses proportional figures, which means dropping tabular-nums from today’s large figure.
  • Text never wears a series colour, status colours only mean good or bad and always come with a word, and the room may change colour while the data may not.
  • Numbers never count up. A counter passes through values that are not true, and this is the one place where everything shown must be. Lines draw in 700 ms, bars grow from the baseline, table rows rise 30 ms apart, a map flies in during the holding line; reduced motion turns each into a cross-fade.
  • Searching panes take the skill’s shape: a dim world for a map, a tile and a faint curve for weather, a 16:9 shimmer for video, and research gains its progress line.

13

Charts and tables

Charts are GIDEON’s own SVG components on four d3 modules (d3-scale, d3-shape, d3-array, d3-time-format) rather than a charting library. Glass needs its own chrome, spoken highlighting needs a hook on every point, the motion rules must hold, the server pass has no canvas, and Recharts alone is 7.4 MB unpacked on npm.

Charts

  • One y-axis, always. Two units become two charts sharing the x-axis.
  • A line needs 4 points; bars need 3 and stop at 15; bars start at zero.
  • At most 5 series; past 4, each is labelled at its end.
  • A missing value is a gap, never a zero; over 400 points is downsampled keeping its shape.
  • 2 px lines, bars ≤ 24 px with 4 px rounded ends, solid hairline grids, at most 5 round ticks.
  • Label the end, the peak, and the series the story is about, never every point.
  • A computed summary, a table view, and the same readout on hover and keyboard.
  • An “as of” date and the source under every chart.

Tables

  • Numbers right-aligned in tabular figures, one precision per column, the unit in the header.
  • The first column stays put when the table scrolls sideways in its well.
  • 12 rows shown; “show all 34” grows the card to feature size instead of scrolling it.
  • Numeric columns sort by tap or by voice.
  • A “best” marker only where the skill declares which direction is better. The model never picks a winner.
  • Missing values are a dash with a note, never a zero.
  • Each cell’s source on hover, through the lens.

Maps

The map itself

  • mapbox-gl 3.30.0, released 3 September 2026, loaded with import() on the first map block and fetched early the moment a show_map call is pending.
  • One map for the whole page. A single mapboxgl.Map is moved into whichever map block is in front. The room’s shader and this map are the only WebGL contexts ever alive, and a session costs one map load.
  • Mapbox Standard, configured: lightPreset: 'night', theme: 'monochrome' or 'faded', POI labels off, colorWater and colorLand tuned toward the room’s blues. Satellite on request.
  • Stills from the Static Images API for the peek, the shelf, no WebGL and data saver.
  • Attribution and the logo stay visible, recoloured only.

Tokens, location, cost

  • MAPBOX_PUBLIC_TOKEN, URL-restricted to chatgideon.com and localhost, sent in ready; still-image URLs use it because the browser loads them.
  • MAPBOX_SERVER_TOKEN, a secret, for geocoding, directions and search.
  • Coarse location by default from request.cf, read in server.ts when the socket opens. Precise only for “near me”, with the browser’s permission, rounded to about 110 m, never stored unasked.
  • Free monthly allowances: 50,000 web map loads, 100,000 temporary geocodes, 100,000 directions, 50,000 static images.

Video

Finding and showing it

  • YouTube Data API v3: embeddable, syndicated, moderate safe search; then duration, description and region.
  • Quota: 10,000 units a day; a search costs 100, so 100 searches; cached by query for 24 hours.
  • Fallback: Exa limited to youtube.com plus oEmbed. The card loses duration and chapters, nothing else.
  • Chapters from at least three timestamped lines in the description, the first at 0:00.
  • Poster first. The youtube-nocookie.com player loads only on play. GIDEON never starts a video by itself. Embed only; nothing downloaded or re-hosted.

A video in a room with an open microphone

  1. Spike first. Three minutes of dialogue at normal volume with echo cancellation on; count the turns that start. Whether the browser cancels the page’s own video audio decides the rest.
  2. If it does not, a turn during playback needs GIDEON’s name or a tap.
  3. Either way, addressing GIDEON pauses the video (not ducks it), and “carry on” resumes.

Gate: zero false turns across those three minutes before video ships.

The front page and the feature

GIDEON speaks like a very formal 1955 letter, so its newspaper borrows the decade: a broadsheet set in glass, drawn above under recipes.

  • The edition follows the user’s clock: morning before noon, afternoon before five, evening after.
  • Stories come from news search with a start date, each dated; older than 48 hours, a story gives its date in full.
  • Headlines ≤ 10 words, decks ≤ 30, written from each story’s own passages and number-checked against them.
  • The lead is the most recent story carried by the most sources; every story carries its own source markers.
  • The feature answers “tell me everything”, “explain”, “the full story”. research gains depth: 'deep': pages read, a second round allowed, the voice still under sixty words. The voice stays short; the card goes deep. Hero picture, headline and deck, two paragraphs with a drop cap, one verbatim pull quote, a facts sidebar, a timeline strip.

The screen as a workspace

The stage judge becomes a stage director. It keeps what made the judge work (asked what a message is about, with code deciding the move) and adds one question: does the message ask to change the open card, and how? The answer must be a control that card declares. A control never fetches; anything needing new data is a new tool call.

Controls

  • Table: sort by a column; highlight a row.
  • Chart: show as a table; highlight a series; change range.
  • Map: zoom; fit; satellite; 3D; focus pin n.
  • Video: play; pause; seek to a chapter or time; mute.
  • Gallery and timeline: open, next, previous; focus an event.

Crafting

  • Records of one kind → a comparison; research fills fields only one has.
  • Places → pins on one map; for two, a route chip.
  • Series in one unit → one trend; in different units → small multiples, never a dual axis.
  • A figure with a history → its trend.
  • By voice (“compare them”) or by dragging a shelf tab onto the front card, where only the crafts those two can make light up.
  • Spreads lay several blocks on a 12-column grid in one feature card. The frame refracts and the tiles are wells, so five tiles cost one displacement map.
  • The shelf survives a reload in IndexedDB: 12 cards at most, put away on restore. A stale card says “From three hours ago” and offers refresh, which re-runs its origin with arguments checked again on the server.
  • The memory card: “What do you remember about me?” lists every memory with a control to forget it. The tap goes over the socket, the server removes it and logs it, and memory becomes answerable and editable where the user is already looking.

19

Speaking in step with the screen

  • Mentions. When a card is made, the server indexes its numbers (normalised as numbersIn() does), years and proper names against the elements they should light. As the caption reveals words on the audio clock, the browser lights those elements: a row, a point, a pin, an event, a chapter. A token that points at more than three elements lights none.
  • The eyes follow. The docked face already takes its gaze from --gaze-x and --gaze-y; when an element lights, the gaze turns toward it for a moment.
  • The speaking model knows the open card through a 400-character digest: a table’s columns and rows, a chart’s series with first, last and peak, a map’s places in order, a video’s chapters. “Which is cheaper?” is answered from what the user can see, and the old rule stands: refer to the card, never read it out.

Security, privacy and licences

What the card may contain

  • No dangerouslySetInnerHTML; charts are React elements built from numbers.
  • Links http/https only; pictures https only; video ids match ^[A-Za-z0-9_-]{11}$; coordinates finite and in range.
  • Colours from tokens; no model output reaches a style.
  • Pages read through Exa; a direct fetch must be https, a public host, under 2 MB, HTML, within 5 s.
  • Secrets in Wrangler secrets and .env, never VITE_; the Mapbox public token is public by design and URL-restricted.

What leaves, and what must be credited

  • YouTube loads nothing until play; Mapbox counts map loads for billing, and the README should say so.
  • A future content security policy must allow Mapbox workers, tiles and events, i.ytimg.com images and youtube-nocookie.com frames.
  • Credit: Mapbox on every map and still; CC BY 4.0 for weather, World Bank and Our World in Data; Wikidata is CC0 and cited anyway; Wikipedia pictures keep their credit line; ECB rates shown as reference rates with their date.
