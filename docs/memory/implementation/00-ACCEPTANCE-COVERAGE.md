## Turn specifications into real tests

For each case, the implementation agent must add:
1. Synthetic actors, scopes, committed event IDs/revisions, clocks and initial database/projection state.
2. The concrete stimulus through the layer being tested: command/API/transport/retrieval/answer.
3. Required record, evidence, receipt, context-pack and user-response assertions as applicable.
4. Forbidden state changes/disclosures, including source and derived copies where relevant.
5. Expected failure behavior, cleanup and an evidence artifact path.
6. A capability status so NOT_IMPLEMENTED and SKIPPED cannot be counted as PASS.

Use deterministic checks for authorization, versioning, receipts and deletion. Use semantic evaluation with audited judges for conversational interpretation. Do not replace storage invariants with a judge asking whether the final answer sounds correct.

Public seed cases are development cases. Independently authored held-out trajectories are required before quality claims. A transport fixture does not prove actual playback; an in-memory adapter does not prove PostgreSQL transactions.
