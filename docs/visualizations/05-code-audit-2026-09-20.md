# Visualization code audit — 20 September 2026

## Finding

The September 19 catalog is a proposal with 22 families, not a list of 22 implemented visualizations. The code does not implement the entire catalog. Passing existing tests cannot establish coverage of families that have no contracts, routing or renderers.

There are eight chart forms in `src/lib/cards/schema.ts`: line, area, column, bar, range, scatter, histogram and heatmap. At the start of this audit, eight research-table skills existed in `src/lib/cards/visualization-skills.ts`: ranking, comparison, trend, timeline, table, scatter, distribution and heatmap. The continuation adds range as a ninth validated research skill. Timeline and table are separate block types, not SVG chart forms.

`src/lib/tools/research.ts` deliberately retains one selected table material per answer: each later `visualize_table` choice deletes the previous selected table material. `cardFromMaterials` selects that material ahead of incidental provider results. Consequently, one answer does not expose every captured table or every compatible visualization as a gallery.

No dedicated market depth/order-book chart was found in these contracts, renderers or the visualization brief. A low/high interval chart, a trend over time, and a time-range selector are separate capabilities.

## Interaction and evidence coverage

Implemented: chart/table toggle; pointer and keyboard readouts; touch-down selection; accessible table values; source links; numeric table sorting; source retrieval dates; null gaps; bounded Markdown-table capture; deterministic histogram calculation; selection/capture reason codes; reduced-motion chart styles; existing stage dispatch and card lifecycle machinery.

The continuation implements native modal chart details with source access and original source-table access when available. Dated line/area charts with more than two observations have From/To controls, visible active-period disclosure and reset. Chart geometry, values, table, summary and annotations share the selected slice; the captured source data is unchanged. These operations require no fetch or model call.

Still not implemented as a general visualization explorer: series visibility controls, chart-form switching, general category filters, linked filtering, multiple selected datasets per answer, export/download of full datasets, or narrative navigation.

Mediation preserves raw cells and row-line evidence internally. The card exposes raw tables and page-level links, but not a per-cell evidence inspector, dataset/version browser, transform-log UI or complete methodology panel. Arbitrary HTML/CSV/OCR extraction, locale inference and multi-table joins remain absent. Observation time and retrieval time are not interchangeable.

## Repairs made during this audit

1. Negative ranked values previously had their bar length clamped to zero. Bars now share a signed scale with a visible zero baseline; keyboard inspection supplies the complete category and exact value.
2. Range readouts previously rounded or abbreviated bounds. Inspection now preserves both numeric endpoints, matching the table.
3. Touch selection now survives the touch pointer leaving the plot; mouse leave and keyboard dismissal still work.
4. Long multi-series end labels no longer consume most of a narrow plot. The legend and table retain the names. Long ranking names are abbreviated in the drawing and available in full through inspection/table/summary.
5. Time-axis label selection accounts for actual spacing. Adjacent calendar observations no longer automatically receive overlapping labels merely because their array indices differ.
6. The older provider-series path now supplies real year positions, matching the captured-table trend path.
7. Chart input exceeding a form's series limit is rejected instead of silently clipping series. Reversed or unpaired low/high bounds are rejected. This is validation, not a new automatic fallback UI for arbitrary malformed chart blocks.
8. The lab's grid items now shrink within mobile viewports. Before this fix, its fixed stage width forced cards outside a narrow viewport.
9. Readout content can wrap within the chart width. Added local renderer fixtures for range precision/nulls, zero-valued area data, signed rankings/long names, and multiple long series names.
10. Added source-table range selection, date-range controls, and expanded chart details. Range selection requires a source-defined bounds label and rejects reversed, unpaired, nonnumeric or incompatible-unit bounds. Empty selected periods deliberately show a no-values state rather than invented marks. Expanded details retain the selected period and leave the underlying card selection intact on dismissal.

## Remaining correctness work

- The provider-material selector still chooses the largest measure group and takes up to five series; that upstream omission needs a visible disclosure and access to omitted data. Reader rejection does not solve that upstream selection.
- Provider series are grouped by measure ID; generic unit/basis compatibility is not independently validated at that boundary.
- A complete catalog implementation needs per-family source contracts and refusal rules. Adding only SVG branches would leave most families unreachable from research and could imply evidence the data does not contain.
- Some old block readers deliberately cap or drop invalid content. Full-data accessibility and explicit omission/failure messages need a cross-block design; rejected chart blocks are not automatically replaced by a detailed source table.
- Compact axis/summary labels remain rounded; exact values belong in inspection and tables. Very long histogram boundary strings and dense labels merit further fixtures before claiming every numerical scale is covered.
- Existing color contrast tests do not establish every heatmap shade, mark, annotation and interaction state meets accessibility requirements. This audit is not exhaustive accessibility certification.
